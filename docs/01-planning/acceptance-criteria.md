# Sabz System Platform
# Milestone Acceptance Criteria

Version: 1.0

---

# Purpose

This document defines the acceptance process for each project milestone.

A milestone is considered complete only after the client reviews the delivered functionality and confirms that the agreed acceptance criteria have been satisfied.

---

# General Acceptance Conditions

Each delivered feature must satisfy the following:

- Functional requirements implemented.
- Acceptance criteria met.
- Major defects resolved.
- Responsive on desktop and mobile browsers.
- Basic security validation completed.
- Integrated with related modules where applicable.
- Demonstrated to the client.

Minor cosmetic issues that do not affect functionality may be scheduled for a later maintenance update and will not delay milestone acceptance.

---

# Milestone 1 Acceptance

The first milestone will be accepted when the client verifies that:

## Authentication

- Customers can register and log in.
- Business partners can submit registration requests.
- OTP verification functions correctly.
- User profiles can be managed.

## Partner Management

- Business documents can be uploaded.
- Operators can approve or reject applications.
- Partner tiers can be assigned.

## Administration

- Administrators can manage users.
- Operators have restricted permissions.
- Products can be created, edited, and archived.
- Categories and brands can be managed.

## Inventory

- Stock quantities can be updated.
- Product availability is reflected correctly.

---

# Milestone 2 Acceptance

The second milestone will be accepted when:

## Storefront

- Customers can browse products.
- Search and filtering work correctly.
- Product detail pages display complete information.

## Shopping

- Shopping cart functions correctly.
- Checkout process is completed successfully.
- Online payments are processed successfully.

## Pricing

- Retail customers see retail prices.
- Approved partners see tier-specific prices.
- Bulk pricing rules are applied correctly.
- RFQ functionality operates for designated products.

## Orders

- Orders are created successfully.
- Customers can view order history.
- Order status is visible.

## CMS

- Blog articles can be created and published.
- Product pages include SEO metadata.

---

# Milestone 3 Acceptance

The third milestone will be accepted when:

## Shipping

- Shipping methods are operational.
- Tracking information can be managed.

## Returns

- Return requests can be submitted.
- Return workflows are completed successfully.

## Notifications

- Required customer and administrator notifications are delivered.

## Performance

- The application performs acceptably under normal expected usage.
- Images and assets are optimized.

## Security

- Role-based permissions function correctly.
- Sensitive actions are protected.
- Audit logs capture administrative actions where applicable.

## Production

- The application is deployed to the production environment.
- Final documentation is delivered.
- Administrator training has been completed.

---

# Client Review Period

The client will have five (5) business days to review each milestone after delivery.

During this period the client may:

- approve the milestone,
- request corrections for items within the agreed scope, or
- report defects.

If no significant issues are reported within the review period, the milestone will be considered accepted.

---

# Revisions

Reasonable revisions related to the approved scope are included within each milestone.

Requests for new functionality or changes to approved requirements will be handled through the Change Request process.

---

# Final Project Acceptance

The project will be considered complete when:

- All three milestones have been accepted.
- All agreed deliverables have been provided.
- The application has been deployed successfully.
- Source code and documentation have been handed over.
- Final payment has been completed in accordance with the project agreement.
